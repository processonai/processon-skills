# 流程图线（生成 DSL → 落库）

> 流程图类图形的完整流程：先用 `generatedDsl` 把用户内容转成图数据（DSL），再把返回的 DSL **原封不动**交给 `createProcessOnFile` 落库到用户 ProcessOn 账号。两步同属 processon 一个 MCP。

> **本文件为内部编排依据，对用户静默执行**（内部术语黑名单见 SKILL.md「严格规则」）；对用户只说「正在为你生成图形…」，完成后给结果与链接。

## 与思维导图线的根本区别（务必先读）

| | 流程图线（本文件） | 思维导图线 |
|---|---|---|
| 内容来源 | `generatedDsl` 生成 DSL | AI 直接写 Markdown |
| content | DSL（原样搬运，不改写） | 纯 Markdown |
| `reqId` | **必传**（来自 `generatedDsl`） | 不传 |
| `structure` | 不传 | 必填 |
| `theme` | 不传 | 必填 |
| `category` | 12 类（兜底 `flowbase`） | `mind_*` |

> 思维导图**不走本文件**，见 `references/mindmap.md`。

## 适用范围

流程图、业务流程图、泳道图、BPMN、时序图、UML 图、系统/软件/云架构图、ER 图、网络拓扑图、韦恩图、电路图、平面图、图表、UI 界面/原型、路线图、信息图、金字塔图、草图重绘等流程或技术类结构化图表。

> 生成侧（`generatedDsl`）能产出的图形形态多于落库侧的 `category` 枚举，这是正常的：**形态由生成侧决定，落库类型按第三节取值，取不到就用兜底 `flowbase`**。

**不适用**：思维导图、脑图、组织结构图、鱼骨图、时间轴、树形图、知识整理/内容总结 → 走 `references/mindmap.md`。

---

## 一、生成前：先补关键信息，不要在信息不足时直接生成

关系不清、流程断层或结构缺失时，按此顺序处理：

1. 指出缺少什么。
2. 给出合理默认方案或行业常见做法供用户确认。
3. 用户确认后再生成。

**仅在分不清走哪条线时才问**：用户只说"画个图"这类完全模糊的请求，先确认要哪种图。**用户已明确图形种类时（如"画个架构图"）直接生成** —— category 取不到对应值就用兜底 `flowbase`，不要为此追问。

**草图/图片重绘**：用户上传图片要求"重绘/转成图"时，先识别图中的节点、文字、连接关系，再构建结构化输入。

## 二、优化内容（在用户原始需求上补专业约束，不改写用户语言）

- **通用**：专业风格、布局清晰、颜色协调、避免线条交叉。
- **流程图**：明确开始/结束节点，决策点用标准菱形。
- **时序图**：参与者清晰，调用消息明确。
- **架构图**：按层次组织，标注关键通信关系；分析项目架构时提取模块边界、依赖、调用链、数据流向，**画关系不画目录树**。
- **ER 图**：标注主外键关系与字段类型。

优化后的内容默认与用户语言保持一致。

---

## 三、category 取值（两步都传同一个值）

`generatedDsl` 与 `createProcessOnFile` 的 `category` **传同一个枚举值**。`category` 决定落库的**文件类型**，当前 12 类：

| 图形类型 | category |
|---------|----------|
| 流程图 | `flowbase` |
| UML 图、**时序图** | `uml` |
| ER 图 | `er` |
| 泳道图 | `swimlane` |
| BPMN 业务流程图 | `bpmn` |
| 韦恩图 | `venn` |
| 网络拓扑图 | `network` |
| **架构图**（系统 / 软件 / 云架构） | `framework` |
| 电路图 | `circuit` |
| 平面图 | `plane` |
| 图表 | `graph` |
| UI 界面 / 原型 | `ui` |

> **兜底规则**：图形类型不在上表内（如路线图、信息图、金字塔图、草图重绘等），**一律传 `flowbase`**，不必为此询问用户。
> 只有在**分不清该走流程图线还是思维导图线**时才需要询问用户。
> `category` 与 `structure` 是**两个不同的东西**，互不等同。流程图线**不传 `structure`**。

---

## 四、编排调用（orchestrator.mjs）

> 流程图线通过本 Skill 自带的 `orchestrator.mjs` 一条命令完成「生成 DSL → 落库」。
> **DSL 在脚本内部流转，不经过 AI 上下文**——AI 只输出优化后的自然语言需求，脚本自动完成 b64 编码 → `generatedDsl` → 解析 DSL+reqId → b64 编码 → `createProcessOnFile`。
> **传参形式用 `参数=值`**；脚本内部直连 MCP，不经 mcporter，无需 `--no-coerce`。

### 新建流程图

```
node scripts/orchestrator.mjs \
  category=<12类之一，兜底 flowbase> title='<文件名>' \
  <<'POB64'
<优化后的自然语言内容原样写在这，单引号 heredoc 不做转义/变量展开>
POB64
```

| 参数 | 必填 | 说明 |
|------|------|------|
| heredoc 内容 | 是 | 优化后的自然语言需求（脚本内部自动 b64 编码） |
| `category` | 是 | 细粒度文件类型，同第三节表 |
| `title` | 否 | 文件名称 |

**脚本返回** = `createProcessOnFile` 的返回（chartId、文件链接、缩略图链接、点数等）。

> 若脚本返回的是 `generatedDsl` 的原始输出（无 chartId / 文件链接），说明步骤 1 失败——按错误码处理（见 `references/errors.md`）。

### 编辑流程图（情况二）

有 `chartId` 时，脚本自动走编辑模式（`generatedDsl` → `updateProcessOnFile`）：

```
node scripts/orchestrator.mjs \
  chartId=<目标文件id> category=<原图类型> title='<原标题>' \
  <<'POB64'
<修改要求原样写在这>
POB64
```

> 编辑的分流判断与参数说明见 `references/edit.md`。

## 五、关键约束

- **DSL 与 reqId 均不出脚本**：`orchestrator.mjs` 内部原样搬运 DSL、自动配对 reqId；**禁止**绕过脚本手工调用 `generatedDsl` 或修改 DSL。
- **两步的 `category` 必须一致**。
- **不传 structure/theme**：这两个是思维导图专用参数。
- **新建无需用户确认**，落在用户账号**根目录**（不支持指定文件夹）。
- 一次一图、重试上限 2 次等通用规则见 SKILL.md「严格规则」与 `references/errors.md`。

**重试安全性**：`orchestrator.mjs`（新建）内部含 `createProcessOnFile`，**每次调用都会新建文件**，不可盲目重试，失败重试前先用 `queryProcessOnFile` 查重，避免重复落库（**查重是只读操作，不计入重试次数**）。`orchestrator.mjs`（编辑）内部含 `updateProcessOnFile`，可重试，结果以最后一次为准。

---

## 六、数据流转

1. 识别图形类型（→ category，兜底 `flowbase`）、提取关键实体/动作/判断条件；信息不足或类型模糊 → 先问用户（仅限分不清走哪条线时）。
2. 按第二节在用户需求上补专业约束，不改写用户语言。
3. 通过 `orchestrator.mjs` 一条命令完成「生成 DSL → 落库」（命令见第四节；脚本内部：b64 编码 → generatedDsl → 解析 DSL+reqId → b64 编码 → create/update）。
4. 从返回拿 chartId（内部留存）、文件链接、缩略图链接，按第七节交付。

---

## 七、返回给用户

按 SKILL.md「统一交付内容」与 `references/examples.md` 的交付模板执行：**文件名 + 类型 + 文件链接 + 文件缩略图链接**（消耗AI点数存在且大于 0 时另加）。本线特有几点：

- **类型**：流程图（由返回的 `categoryParent` 判定，`flow`=流程图）。
- `chartId` 仅内部留存（保留在上下文，供后续编辑定位），不展示给用户。
- **必须在内置浏览器打开文件链接**：拿到返回后，用当前载体的内置浏览器打开**文件链接**（`present_files` 传文件链接，不传缩略图链接），让用户直接在右侧浏览器查看或编辑。
- **必须在新页签打开**：一次只提交当前这一个文件的链接，新文件落在**新页签**，不覆盖、不替换用户此前已打开的其他文件页签。
- **提示语加粗 + 降级**：**仅当内置浏览器确认打开成功时**，另起一段**加粗**输出「**已在右侧浏览器已打开该文件，您可进行查看或编辑→→**」，紧跟文件信息块之后；**内置浏览器不可用 / 打开失败 / 未确认成功**时**省略该句**，改说「可点击链接查看与编辑」，严禁谎称已打开。
